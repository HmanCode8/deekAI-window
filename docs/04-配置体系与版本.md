# 04 · 配置体系与版本

配置体系要同时解决两个互相冲突的需求：

1. **普通用户不该看到、也改不动后端基础设施**（Supabase 地址、Key 这类东西不可能让用户填）；
2. **用户需要能配自己的模型 Key**（BYOK）；
3. **开发者/自托管者要能改一切**。

解法是**三层配置 + 两类版本（edition）**。

## 1. 三层配置

| 层 | 来源 | 谁维护 | 桌面端位置 | 网页端位置 |
|---|---|---|---|---|
| `published` 发行内置 | `app-config.json` | 你（运营方），随包下发 | 安装目录 `resources/app-config.json` | 项目根 `app-config.json` |
| `base` 部署环境 | `.env` 文件 + 进程环境变量 | 部署方 | `<应用目录>/.env`、`resources/.env`、`cwd/.env` | `cwd/.env`、`cwd/.env.local` |
| `override` 用户设置 | `config.json` | 使用者（设置面板写入） | Windows：`%APPDATA%\<应用名>\config.json`（发行版为 `DeekAI`，开发时是 `deekai-desktop`） | `<dataDir>/config.json` |

核心逻辑集中在 `src/shared/config-core.ts` 的 `ConfigCore` 类，桌面端（`src/main/config.ts`）与网页端（`src/server/config.ts`）都只是**薄封装**——各自负责把"路径"和"发行内置配置"喂进去，合并/校验/脱敏逻辑完全共用。

> 桌面端非打包运行时，`userData` 会被改到项目内的 `.dev-profile`，所以开发时用户配置在 `<项目>/.dev-profile/config.json`。

## 2. 两类配置键

```ts
// 基础设施键（运营方）：普通用户不可见、不可改
INFRA_KEYS = [DATA_STORE, SUPABASE_URL, SUPABASE_ANON_KEY,
              SUPABASE_SERVICE_ROLE_KEY, PUBLIC_WEB_URL]

// 模型键（使用者）：用户可覆盖，BYOK
MODEL_KEYS = [DEEPSEEK_API_KEY, DEEPSEEK_BASE_URL, DEEPSEEK_MODEL]
```

### 取值优先级

| 键类别 | 优先级（左高右低） |
|---|---|
| 基础设施键（release） | 发行内置 → 部署环境 → 用户配置 |
| 基础设施键（advanced） | **用户配置** → 发行内置 → 部署环境 |
| 模型键（两种版本一致） | **用户配置** → 发行内置 → 部署环境 |

（基础设施键在 `release` 下把"用户配置"放在最后，只是为兼容早期自托管用户留下的存量数据；正常不会有值。）

### 写白名单

`save()` 只接受当前版本允许的键，其余一律丢弃：

| edition | 可写键 |
|---|---|
| `release` | 仅 `MODEL_KEYS` |
| `advanced` | 全部键 |

**这就是"用户改不动后端配置"的实现机制**——即使有人在 release 版里手改 `config.json` 塞进 `SUPABASE_URL`，加载时也会被 `filterWritable` 过滤掉，永远不会生效。

另：设置面板提交**空字符串表示清除该键**（`save` 里执行 `delete`），"清除本机设置"就是一次全键传空串的操作。

## 3. 两类版本（edition）

### 判定优先级

```
启动环境变量 DEEKAI_EDITION  >  .env 文件里的 DEEKAI_EDITION  >  app-config.json 的 DEEKAI_EDITION  >  "release"
```

默认 `release`——**宁可少给权限，也不能把内部配置暴露给普通用户**。

打包脚本 `scripts/prepare-release-config.mjs` 会强制把 `DEEKAI_EDITION` 写进生成的内置配置，避免忘记设置。

### 行为差异

| | `release` 发行版 | `advanced` 自托管版 |
|---|---|---|
| 面向 | 普通用户 | 你自己 / 自托管者 |
| 设置面板 | 账号 / 我的模型 / 外观 / 关于 | 额外含 **数据存储 / Supabase / 分享** |
| 控制字段 | `canEditInfra === false` | `canEditInfra === true` |
| 能改 Supabase | 否（白名单拦截） | 是 |
| 「关于」文案 | 「本版本已内置后端与站点配置，无需填写；如需自托管…设置 DEEKAI_EDITION=advanced 后启动。」 | 显示 `数据目录：…` |
| 打包产物 | `DeekAI-Setup-*.exe`（appId `com.deekai.desktop`） | `DeekAI-Advanced-Setup-*.exe`（appId `com.deekai.desktop.advanced`，可与发行版同机共存） |
| 输出目录 | `release/` | `release-advanced/` |

`canEditInfra` 由 `PublicConfig` 下发（`edition === "advanced"` 派生），设置面板只凭这一个字段决定是否渲染那三个分区。

### 本地开发怎么进 advanced 模式

因为项目根目录存在 `app-config.json`（`release`），本地 `npm run dev` / `npm run dev:web` 默认也是 release 模式，看不到 Supabase 配置。想调试完整面板，在项目根建一个 `.env`：

```
DEEKAI_EDITION=advanced
```

或临时用环境变量：`$env:DEEKAI_EDITION="advanced"; npm run dev:web`

## 4. 环境变量清单

完整示例见 `.env.example`。

| 变量 | 用途 | 备注 |
|---|---|---|
| `DEEKAI_EDITION` | `release` / `advanced` | 见上 |
| `DEEPSEEK_API_KEY` | 模型 API Key | 留空则要求用户自带（BYOK） |
| `DEEPSEEK_BASE_URL` | 模型服务地址（OpenAI 兼容） | 默认 `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 默认模型名 | 前端选择器有独立清单，此项作为兜底 |
| `DATA_STORE` | `memory` / `supabase` | 留空时：Supabase 配齐即 `supabase`，否则 `memory` |
| `SUPABASE_URL` | Supabase 项目地址 | |
| `SUPABASE_ANON_KEY` | 公开 key，前端可见 | |
| `SUPABASE_SERVICE_ROLE_KEY` | 仅"老数据认领"用 | **桌面端不需要** |
| `PUBLIC_WEB_URL` | 网页端部署地址 | 用于拼分享链接 |
| `SERVER_PORT` / `PORT` | 网页端服务端口 | 默认 `8787`；Vite 代理读同一套变量 |
| `SERVER_DATA_DIR` | 网页端可写目录 | 默认 `./server-data` |
| `SERVER_CONFIG_PATH` | 网页端用户配置文件路径 | 默认 `<dataDir>/config.json` |

**存储模式的实际判定**（`computeStore()`）：

```
DATA_STORE === "memory"                      → memory
DATA_STORE === "supabase" 或留空              → SUPABASE_URL 与 ANON_KEY 都在 ? supabase : memory
其他值                                        → memory
```

## 5. 模型接入与 BYOK

### 任意 OpenAI 兼容服务

请求地址是拼出来的，不是写死的：

```ts
resolveChatCompletionsUrl(baseUrl) => `${(baseUrl || "https://api.deepseek.com").replace(/\/+$/, "")}/chat/completions`
```

所以用户完全可以填 `https://api.moonshot.cn/v1`、`https://openrouter.ai/api/v1` 之类的地址。请求体是标准的 `{ model, messages, stream: true }`，逐行解析 `data: {...}` 的 SSE。

### 模型选择顺序

```
消息里含图片附件  →  强制 deepseek-v4-flash-vision-exp
否则             →  用户选的模型  ||  DEEPSEEK_MODEL  ||  "deepseek-v4-flash"
```

### 一个能力限制：图片上传只认 DeepSeek 官方

图片是走模型服务的 **Files API**（`POST {base}/files`，`purpose=user_data`）上传后引用 `file_id` 的。这是 DeepSeek 官方的接口形态，所以做了能力检测：

```ts
supportsFileUpload(baseUrl) => (baseUrl || 官方地址).toLowerCase().includes("api.deepseek.com")
```

不满足时报错并给出可操作提示：换成文档类附件，或把 Base URL 改回 DeepSeek 官方地址。**文档类附件不受此限制**（纯本地解析，不发上游）。

## 6. 前端能看到的配置（PublicConfig）

渲染进程调 `getConfig()` 拿到的只有这些，**不含任何密钥**：

| 字段 | 说明 |
|---|---|
| `store` | 实际生效的存储模式 |
| `supabaseConfigured` | URL + anon key 是否齐全 |
| `supabaseUrl` / `supabaseAnonKey` | 公开值（前端要直连 Supabase） |
| `deepseekConfigured` | 是否已配 Key（**只有布尔值，不回显 Key**） |
| `model` / `modelBaseUrl` | 默认模型与地址（用于设置页回显） |
| `publicWebUrl` | 分享站点地址 |
| `edition` / `canEditInfra` | 版本与权限 |
| `configSource` | 配置来源说明，如「发行内置配置 + 用户设置」 |
| `appVersion` / `userDataDir` | 版本号与数据目录（关于分区展示） |

设置面板里 `API Key` 与 `Service Role Key` 两个输入框**永远是空的**，placeholder 提示「已配置 · 留空保持不变」。

## 7. CSP 与网络白名单

`src/renderer/index.html` 内联了 CSP：

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https:; font-src 'self' data:;
connect-src 'self' ws: http://localhost:* http://127.0.0.1:*
            https://*.supabase.co https://api.deepseek.com
```

需要注意的两点：

1. **渲染进程不直连模型服务**，模型请求由主进程/服务端发出，所以换 `DEEPSEEK_BASE_URL` **不需要**改 CSP。
2. 渲染进程要直连 Supabase，`connect-src` 里放的是 `https://*.supabase.co`。**如果你用自建域名 / 非 supabase.co 域名的 Postgres 网关，必须同步改这里**，否则请求会被浏览器拦掉。
3. `img-src` 里的 `blob:` 与 `data:` 是为头像与附件预览准备的；头像走的是 `data:`（`FileReader`），刻意避开了 blob URL。

## 8. 常见配置场景

### 场景 A：发行版（给普通用户）
1. 复制 `app-config.example.json` 为 `app-config.json`，填 `SUPABASE_URL` / `SUPABASE_ANON_KEY`（可选 `PUBLIC_WEB_URL`）。
2. `DEEKAI_EDITION` 留 `release`（打包脚本也会强制写入）。
3. 不填 `DEEPSEEK_API_KEY`（纯 BYOK），或填一个作为统一额度。
4. `npm run dist:win`。

### 场景 B：自托管自用
`.env` 里写 `DEEKAI_EDITION=advanced` + Supabase 三项（含 service_role）+ 自己的 Key，`npm run dev` 或 `npm run dist:win:advanced`。

### 场景 C：网页端部署
1. `npm ci --omit=dev`
2. `npm run build:web`（产出 `out/web` 与 `out/server/index.cjs`）
3. 准备好 `app-config.json` 或 `.env`
4. `npm run start:web`（或直接 `node out/server/index.cjs`），端口读 `SERVER_PORT ?? PORT ?? 8787`
5. 记得执行 `supabase/migrations/create_shared_conversations.sql`，并把部署域名写回 `PUBLIC_WEB_URL` 才能生成可用的分享链接。
