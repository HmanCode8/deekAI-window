# 02 · 功能详解

本文按"用户能感知到的功能"逐项说明，并标注实现位置。功能实现高度集中在 `src/renderer/src/components/Chat.tsx`（约 1200 行）。

---

## 1. 会话与项目分组

### 会话
| 操作 | 行为 |
|---|---|
| 新建对话 | 侧栏顶部「新建对话」，或项目组内的 `+`。生成 `crypto.randomUUID()` 作为 id，标题固定为「新对话」，插入列表头部并选中 |
| 切换会话 | 点击列表项。切换时中止当前流、清空输入区与待发送附件、关闭各类菜单 |
| 重命名 | 悬停显示铅笔图标 → 内联输入框；Enter 确认、Escape 取消；`trim() || 原名`（空值回退） |
| 删除 | 悬停显示垃圾桶 → 直接从列表移除；若删的是当前会话，自动切到列表第一项 |

### 项目（分组）
| 操作 | 行为 |
|---|---|
| 新建项目 | 侧栏「新建项目」→ 内联输入行，Enter 确认 / Escape 取消 / 失焦提交 |
| 重命名 | 组头部铅笔图标 |
| 删除 | 组头部垃圾桶，`window.confirm` 提示「删除项目「X」？项目下的会话将移至"未分组"。」——**只删分组，会话会被移到"未分组"** |
| 折叠/展开 | 点击组标题，箭头 `ChevronRight` / `ChevronDown` 切换，头部显示会话数量。折叠状态仅存内存，**不持久化** |
| 拖拽移动会话 | 会话项可拖拽（`draggable`），拖到分组容器上时高亮 `.drag-over`，放下即移动到该组。「未分组」用伪 key `__ungrouped__` 渲染 |

未分组会话统一出现在底部「未分组」组里。会话也可以通过每项的「移动到项目」菜单移动（`moveMenuFor` 状态控制，菜单里当前所属项带 `.selected`）。

### 侧边栏折叠
顶部 `Menu` 按钮切换侧栏折叠，状态写入 `localStorage` 的 `deekai:sidebar:collapsed`（`"1"`/`"0"`），刷新后保持。

## 2. 对话

### 流式输出
- 发送后立刻插入一条空的 assistant 消息作为占位，随后 token 逐个追加（`setAssistantContent` 会替换该会话最后一条 assistant 消息的 `content`）。
- 消息列表自动滚动到底部，但**只有当你本身就在底部附近（距底 < 140px）时才跟随**——向上翻看历史时不会被强行拉回。

### 停止生成
回复过程中输入区上方出现回复状态条 `.reply-bar`（转圈 +「AI 正在回复中…」+「停止」按钮）。点停止会 abort 上游请求，已生成的内容保留。

### 重新提问
每条消息下方有「重新提问」（`RotateCcw`）。对用户消息点它 → 截取到该条为止重新发；对助手消息点它 → 丢弃该条助手回复重新生成。流式进行中或上传中按钮禁用。

### 模型选择
头部下拉框列出**当前账号**可用的全部模型条目 = 「我的模型」（本机按账号保存）+「内置模型」（运营方预置），显示格式为 `自定义名称（厂商实际模型名）`。

配置条目是一个列表，每条包含：自定义显示名、厂商、Base URL、厂商真实模型名、自己的 API Key。你可以加任意多条（例如「快速问答 → gpt-4o-mini」「深度思考 → deepseek-v4-pro」「本地模型 → Ollama」），对话时随时切换。上传或流式进行中时禁用切换。

**模型清单按账号隔离**：
- 「我的模型」存在**本机** `localStorage` 的 `deekai:models:<userId>` 里，只有本账号可见；同机换账号、网页端换浏览器用户都互不可见、互不覆盖，也不会同步到其他设备。退出登录、关闭应用都不会清除。
- 「内置模型」由运营方随包 / 部署预置（`app-config.json` / `.env`），所有人共享且**只读**（带锁标记，无编辑/删除按钮）。
- 调用模型时，本机条目的地址与 Key 随请求带给后端，**服务端只转发不落盘**。

**DeepSeek 是内置保底条目**：即使一条都没加，运营方配置里通常也会有一条「DeepSeek（内置）」，它由 `DEEPSEEK_API_KEY / DEEPSEEK_BASE_URL / DEEPSEEK_MODEL` 三个配置合成；运营方没配 Key 时，用户在自己的本机条目里填 Key 即可使用。

厂商预设（用于自动带出 Base URL 与候选模型）：

| 厂商 | Base URL | 图片附件 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | 支持 |
| OpenAI | `https://api.openai.com/v1` | 不支持 |
| 通义千问（阿里云百炼） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 不支持 |
| Kimi（Moonshot） | `https://api.moonshot.cn/v1` | 不支持 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | 不支持 |
| 硅基流动 SiliconFlow | `https://api.siliconflow.cn/v1` | 不支持 |
| OpenRouter | `https://openrouter.ai/api/v1` | 不支持 |
| 豆包（火山方舟） | `https://ark.cn-beijing.volces.com/api/v3` | 不支持 |
| 自定义（OpenAI 兼容） | 手填 | 取决于地址 |

预设里的模型清单只是"常见型号"，会过时。真实可用的列表可以点编辑表单里的「从服务端获取」——它会调 `GET {baseUrl}/models` 拿服务端返回的列表（需要该服务支持这个接口），也可直接手填。

### 会话标题
**没有模型自动起标题**。标题规则只有一条：取首条用户消息的**前 20 个字符**。触发时机有两处——发送时若标题还是「新对话」就替换；没有选中会话时新建即以该规则命名。

## 3. 附件与文件解析

### 支持的类型

| 类型 | 处理方式 | 限制 |
|---|---|---|
| 图片（jpg/jpeg/png/gif/webp） | 上传到模型服务的 Files API，拿到 `file_id` 后在对话中引用 | **只有声明了 Files API 的条目可以**（目前仅 DeepSeek 官方）；其它条目会在选择文件时就被本地拦下并提示 |
| PDF | 后端 `pdf-parse` 抽文本 | 抽出的文本上限 **12000 字**，超出截断并标记 `[内容已截断]` |
| DOCX | 后端 `mammoth.extractRawText` | 同上 |
| 文本/代码（txt/md/csv/json/yaml/xml/html/css/js/ts/tsx/py/java/go/rs/c/sql/log/ini/env…） | 直接按 UTF-8 读 | 同上 |

单文件上限 **64MB**。上传成功但抽不到文本（扫描件、图片型 PDF）会明确报错提示。

**文档类附件与厂商无关**——它是本地解析后拼进提示词，所以任何模型条目都能用；只有图片依赖服务商的 Files API。

### 交互
- 输入框左侧回形针按钮，或直接 **粘贴文件**（`onPaste` 捕获 `clipboardData` 里的 file 项）。
- 支持多选、多文件并行上传。
- 待发送附件以 chip 展示：`图片`/`文档` + 文件名 + `×` 移除。
- 图片附件且当前不是视觉模型时，chip 上会提示「将自动切换视觉模型」——**这只是提示**，渲染层的 `model` 状态不变，真正的切换发生在后端（见下）。

### 模型侧的两种降级
`src/backend/deepseek.ts` 里：
1. **只有当条目声明了视觉模型、且消息里含图片附件时才切换模型**。目前只有 DeepSeek 条目声明了 `visionModel`，此时会改用 `deepseek-v4-flash-vision-exp`；其它厂商的模型名不会被覆盖（它们本来也传不了图片）。
2. 若条目拿不到 `file_id`（即不具备 Files API），图片不会被丢弃，而是降级成一句文字说明「用户还上传了图片文件：xxx」，避免模型完全不知情。

这套逻辑由配置层解析出的条目信息驱动（`ResolvedModel.supportsFiles` / `visionModel`），后端不认识具体厂商，将来给别的厂商加上 Files API 支持也不用改这里。

文档类附件则统一拼成一段上下文插入用户消息：

```
以下是用户上传文件的解析内容，请结合这些内容回答：

[文件 1] report.pdf
<抽取出的正文>
```

## 4. 会话分享（只读链接）

入口：头部 `Share2` 按钮。**仅云存储（supabase）模式可用**，内存模式点它会弹提示。

流程：
1. 生成 **128bit 随机 token**（`crypto.getRandomValues(16 字节)` → 32 位十六进制）。
2. 把会话**当时的快照**（标题、所属项目名、全部消息）写入 Supabase 表 `shared_conversations`。
3. 拼接链接：优先用配置的 `PUBLIC_WEB_URL`，其次当前页面 origin，桌面端 `file://` 且未配置时返回相对 `#/share/<token>`。
4. 本机把「会话 id → token」记到 `localStorage` 的 `deekai:share:<conversationId>`，便于再次打开弹窗时展示与撤销。

链接形如 `https://your-site.com/#/share/<token>`，**打开无需登录**，页面显示标题、项目名、分享时间、消息总数和「只读」标记。

撤销：弹窗里「撤销分享」→ `window.confirm` → 删除该 token 对应行，**原链接立即失效**。

> 表结构、RLS 策略见 [03-数据与账号体系.md](./03-数据与账号体系.md#4-会话分享表)；若你的库里还没有这张表，需要先执行 `supabase/migrations/create_shared_conversations.sql`。

## 5. 导出 PDF

入口：头部 `FileDown` 按钮。

实现思路是**复用已经渲染好的消息 DOM**，而不是重新拼一遍 Markdown：

1. 克隆 `.message-list` 节点，移除交互元素（`.msg-actions`、`.copy-btn`、`.attachment-remove`）。
2. 套上内联打印样式 `PRINT_CSS`，生成一份完整 HTML 文档（含标题、导出时间、消息数、页脚）。
3. 文件名取自会话标题：非法字符替换为 `_`、截断 60 字符，追加时间戳 `YYYYMMDD-HHmm`。

落地方式两端不同：

- **桌面端**：弹系统保存对话框 → 把 HTML 写到临时文件 → 用一个隐藏窗口 `loadFile` → `webContents.printToPDF({ printBackground: true, pageSize: "A4" })` → 落盘 → 销毁隐藏窗口并删临时文件。返回 `{saved: true, path}`。
- **网页端**：`window.open("", "_blank")` → `document.write(html)` → 等 350ms → `print()`，由用户在打印对话框里选「另存为 PDF」。弹窗被拦截时返回 `{saved: false}`。

打印样式要点：消息块 `page-break-inside: avoid` 避免跨页断裂；头像固定 26×26 且 `<img>` 用 `object-fit: cover` 约束（否则会撑成大图）；代码块保留深色底 `#0d1117` 且 `white-space: pre-wrap; word-break: break-word`；开启 `-webkit-print-color-adjust: exact` 保证底色能打出来。

## 6. 主题与头像

### 主题
三种模式：浅色 / 深色 / 跟随系统。存在 `localStorage` 的 `deekai:theme`（默认 `system`）。

- 实际生效值写在 `<html data-theme="light|dark">` 上，由 `globals.css` 的深色覆盖块接管。
- 选「跟随系统」时会监听 `matchMedia("(prefers-color-scheme: dark)")` 的 `change` 事件动态切换。

### 头像
- 保存在本机 `localStorage`，key 为 `deekai:avatar:<userId>`（内存模式是 `deekai:avatar:local`），**按账号隔离、不上传服务器**。
- 选图后：校验是图片 → `FileReader.readAsDataURL` 读入（刻意不用 `URL.createObjectURL`，因为 CSP 的 `img-src` 限制）→ canvas 居中裁剪成方图、铺白底 → 导出 JPEG(0.85)。
- 上传/移除会派发 `deekai:avatar-changed` 事件，`useAvatar` hook 订阅后即时刷新界面，无需刷新页面。
- 用户消息气泡左侧显示头像，没有头像则显示默认人形图标。

## 7. 从网页唤起桌面端

仅在网页端出现该入口（头部 `Monitor` +「桌面端」按钮，条件是 `api.bridgeKind === "web"`）。

点击后：把「当前会话 id + 输入框草稿」拼成自定义协议链接

```
deekai://open?conversation=<id>&draft=<文本>
```

跳转该链接。若系统装了桌面端，会唤起（或复用已运行实例）并把会话 id 与草稿带过去；草稿长度上限 2000 字符。跳转后界面顶部出现一条提示条（6 秒后自动消失），提示"已尝试唤起桌面端；若未安装…"。

桌面端侧的接收逻辑：主进程 `second-instance` / `open-url` → `emitDeeplink()` 广播给窗口，同时缓存到 `pendingDeeplink`；渲染端既订阅事件（运行中唤起），也会在挂载后调 `deeplink:consume` 取一次启动时缓存的参数（消费即清空，避免刷新后重复套用）。拿到后：切到指定会话、把草稿填进输入框。

## 8. 登录、引导与内存模式

### 登录 / 注册（`pages/Login.tsx`）
- 邮箱 + 密码，直接走 Supabase Auth。
- 前端校验：邮箱正则、密码至少 6 位。
- 注册后若返回没有 session（说明开了邮箱验证），提示「注册成功！请前往邮箱点击验证链接后回到应用登录。」并切回登录页。
- 错误文案做了中文映射（`src/shared/bridge-api.ts` 的 `AUTH_ERROR_MESSAGES`）：`invalid_credentials` → 邮箱或密码错误、`email_not_confirmed` → 邮箱尚未验证…、`user_already_exists` → 该邮箱已注册…、`weak_password` → 密码强度不足…、`over_email_send_rate_limit` → 验证邮件发送过于频繁…；未命中的错误码回退原始 message。
- 登录成功后由 `onAuthStateChange` 自动进入聊天界面，页面本身不做跳转。

### 引导页（`pages/Onboarding.tsx`）
Supabase 未配置时出现，两个出口：
- 「去设置并配置」→ 打开设置面板；
- 「先以内存模式试用（关闭后数据不保留）」→ 进入 `store="memory"` 的聊天。

### 内存模式
- 不加载、不保存任何数据，全部只存在组件 state 里，关掉即丢。
- 侧栏底部状态显示「内存模式」而非「已持久化」。
- 顶部有 `.memory-banner`，可「打开设置接入云存储」或「返回引导」。

## 9. 其他界面细节

| 位置 | 内容 |
|---|---|
| 侧栏底部 | `设置` 按钮（唯一入口）+「Powered by DeepSeek」+ 持久化状态（未就绪时不显示） |
| 头部 | 侧栏折叠按钮、模型条目选择、分享、导出 PDF、桌面端（仅网页端） |
| 空态 | `Sparkles` 图标 +「DeekAI」+「有什么可以帮你？」 |
| Markdown | 助手消息走 `react-markdown` + GFM 表格 + 代码高亮；代码块右上角有「复制 / 已复制」按钮 |
| 设置面板 | 分 **Tab**：`用户设置`（账号 / 外观 / [数据存储 / Supabase / 分享，仅 advanced] / 关于）与 `模型设置`（我的模型，本机可编辑 + 内置模型，只读） |

### 设置面板的 Tab 结构

弹窗壳只负责标题与 Tab 切换，内容由 `src/renderer/src/components/settings/` 下的组件承担：

```
[用户设置] [模型设置]        ← TABS 数组，加一项 + 写一个组件即可扩展
```

- **用户设置**：账号（邮箱/头像/退出登录）、外观（浅色/深色/跟随系统）、后端基础设施（仅 `canEditInfra` 为真时出现）、关于。
- **模型设置**：分为两块——
  - 「我的模型」（本机保存，仅本账号可见）：条目列表（默认标记、Key 状态、图片能力）+「添加模型」，可编辑/删除，保存到本机 `localStorage`；
  - 「内置模型」（运营方预置，只读）：只展示名称、厂商、模型与能力标签，带「只读」标记，无编辑/删除按钮。
  - 编辑态字段为 显示名称 / 服务商 / API Base URL / API Key / 模型（带「从服务端获取」）。

用户设置 Tab 提交的仍是 `config-core` 的配置键（release 下实际不可写，advanced 仅基础设施）；模型设置 Tab **完全不经过后端**，直接写本机存储。这为后续新增 `智能体` / `MCP` / `Skill` 等 Tab 留好了位置。

## 10. 目前**未实现**的能力

明确列出，避免误解：

- **消息级复制按钮**：只有 Markdown 代码块内有复制按钮，整条消息没有。
- **会话拖拽排序**：拖拽只用于"移动到项目分组"，不支持在同一列表内换序。
- **项目折叠状态持久化**：`collapsed` 只是内存里的 `Set`，刷新即还原为全部展开。
- **条目级的模型参数**：没有 temperature / top_p / max_tokens 等每模型高级参数，如需使用不同参数目前只能建多条条目分别指向不同模型。
- **模型自动生成会话标题**：标题恒为「首条用户消息前 20 字」。
- **服务端搜索 / 分页**：会话全量加载，`saveChatState` 也是整表替换（见下篇）。
- **多设备实时同步**：没有 Realtime 订阅，另一个设备改的数据要刷新才看得到。
- **按条目分别记录用量 / 计费**：没有 token 统计或费用预估。
